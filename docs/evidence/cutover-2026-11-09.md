## Step 12: functional smoke

- A run started through the MCP invoke tool as the invoker Aisha (her password given only to the server process for that run). The flagship opened a CRITICAL request needing 2 approvals (ADA and SOL escalated).
- Slack received the notice once, with the single approval link.
- Aisha's attempt to approve her own run: 403 `SOD_SELF_APPROVAL`, journaled.
- Sarah approved (recorded, not yet decided), then Marcus approved; the request was decided and committed.
- Ledger for the run, 13 rows: STARTED, 7 ASSET_RECONCILED, HITL_REQUESTED, NOTIFICATION_SENT, HITL_APPROVAL_RECORDED, HITL_RESOLVED, COMMITTED. The MCP showed APPROVED, 2 of 2.
- A second run, started by mistake, was rejected by Sarah: HITL_RESOLVED (REJECTED), then COMMITTED with status ROLLED_BACK (the designed terminal record for a rejection).
- **What this does not prove:** the owner entered both approvals and the rejection, signed in as each demo identity in turn. The smoke proves that the system requires two distinct identities, neither of them the invoker; it does not prove two different people (DL-8). No failure path was exercised on live.
